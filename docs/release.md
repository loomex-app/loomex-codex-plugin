# Loomex plugin release and installation

Version 0.1.0 is a portable private, macOS arm64 Codex plugin. The release payload contains bundled JavaScript and a private Node.js 24.20.0 LTS runtime whose upstream archive is pinned by SHA-256. It does not use a GUI process's `PATH`, current directory, `PLUGIN_ROOT`, or undocumented plugin environment variables. After release verification, the installer derives `.mcp.json` from the signed template with absolute paths under the target user's stable `current` installation link. No build-machine home path is present in release bytes.

`scripts/build-release.sh --production` requires a clean committed source revision and builds from a temporary `git archive` snapshot of that exact revision. It runs `npm ci`, type checking, tests, and the compiled bundle build. It downloads the pinned Node archive (or accepts `LOOMEX_NODE_ARCHIVE`), checks its digest, validates the plugin manifest and entrypoints, signs the runtime with hardened runtime options and the minimal JIT entitlement required by V8, and runs a post-sign JIT launch check. It rejects any payload containing the build machine's home path, emits a create-only deterministic release envelope, signs its canonical manifest, requires an `Accepted` Apple notarization result, and performs code-signature and Gatekeeper assessment. Production requires `LOOMEX_CODESIGN_IDENTITY`, `LOOMEX_NOTARY_PROFILE`, and `LOOMEX_MANIFEST_SIGNING_KEY`.

This Mac currently has zero valid code-signing identities. Production release and installation verification are therefore blocked. Nothing in this repository or CI output should be described as a signed, notarized, or release-verified production artifact until a Developer ID Application identity, Apple notarization profile, and offline manifest-signing key are provisioned and the production command succeeds.

For isolated tests only, `scripts/build-release.sh --unsigned-development` emits an artifact marked `developmentOnly`. Installation additionally requires `--allow-unsigned-development` and `LOOMEX_ALLOW_UNSAFE_DEV_INSTALL=1`. Development artifacts must not be distributed or installed into a normal user environment.

The installer verifies signature policy, project and platform provenance, payload digest, every file digest/mode/size, safe archive paths, production code signature and Gatekeeper acceptance, manifest component paths, and the signed launcher template before moving a staged directory into place. It then generates only the local absolute launcher metadata and validates its runtime and server targets. It switches the `current` symlink atomically and refuses to overwrite an existing version. Register the stable `current` path as the private marketplace root (`.agents/plugins/marketplace.json`, source `./plugin`) and install `loomex` from `loomex-private`; upgrades keep that registered marketplace and the generated MCP launcher valid while changing the version target atomically. This intentionally leaves Codex configuration changes to the user-visible Codex marketplace flow.

The package allowlist excludes Git metadata, environment files, credentials, secrets, development dependencies, npm caches, test output, logs, and coverage. Uninstall removes only the `current` link and exact version directory owned by this installer. Disable/remove the plugin marketplace in Codex first so Codex does not retain a cached active copy.

CI runs `npm ci`, `npm run typecheck`, `npm test`, `scripts/test-packaging.sh`, and `scripts/test-node-runtime.sh`. Packaging tests use an explicit temporary install root, accept only an explicitly marked unsigned fixture, prove deterministic output and payload-tamper rejection, reject development/cache paths, validate absolute launcher binding, install atomically, and remove only fixture-owned files. The runtime test downloads the official pinned archive, verifies its digest and reported version, and starts the compiled MCP server with that exact Node binary. CI then installs Codex CLI 0.146.0 on its disposable host, adds the generated private marketplace, installs the plugin through the real Codex command, checks discovery, and removes both entries.
